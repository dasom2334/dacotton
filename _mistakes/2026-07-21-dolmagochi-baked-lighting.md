## 그림을 만드는 것보다 옮겨 설명하는 일이 길어졌다

GPT에서 캔버스 시안을 만들고 Claude에게 가져와 게임에 넣는 방식으로 작업했다. 시안에서 마음에 든 부분이 실제 장면에서도 같게 보이려면 소품의 모양과 위치, 그림자, 빛, 가장자리의 어두움, 움직임을 하나씩 짚어야 했다. 한 번 설명해서 끝나는 것이 아니라 결과를 보고 다시 설명하는 일이 이어졌다. 이 왕복에 지쳤고, 매번 같은 방식으로 방을 만들 수는 없겠다고 느꼈다.

## 반복해서 설명하던 요소를 따로 다루기

7월 19~20일 거실에서는 완성된 그림을 통째로 고치는 대신, 장면을 이루는 요소를 분리했다. 물건의 형태와 색, 그 물건이 받는 빛, 그림자와 움직임을 각각 다루게 했다. 조명 분리는 이 제작 과정을 정리하는 한 부분이었다.

| 분리한 요소 | 이후 조정하는 방식 |
|---|---|
| 소품 | 형태·위치·표시 여부를 개별 데이터로 관리 |
| 팔레트 | 색을 한곳에서 바꾸고 시간·계절별로 적용 |
| 광원 | 빛의 모양과 색·세기를 나눠 조절 |
| 그림자 | 소품의 표시 여부와 빛을 가리는 영역을 연결 |
| 비네트 | 화면 가장자리의 어두움과 강도를 별도로 조절 |
| 애니메이션 | 불꽃·김·날씨 등의 움직임을 정적인 그림과 분리 |

## 코드 세 군데를 고치는 대신 역할별 모듈로

처음에는 생성 스크립트와 CSS, HTML 조립 코드에 장면의 규칙이 흩어져 있었다. 이를 JavaScript의 팔레트·광원·렌더러·애니메이션·소품 모듈로 정리하고 Canvas에서 그리도록 옮겼다. 색 하나를 바꾸려면 팔레트를, 움직임을 바꾸려면 애니메이션을 보면 되게 했다. 기존 Python 생성기와의 결과는 사각형 데이터 1,151개를 대조해 확인했고, 장면을 수정할 때마다 HTML을 다시 생성하던 단계도 없앴다.

## “조금 더 밝게”를 말하는 대신 화면에서 조절하기

레이어 인스펙터에서는 소품과 광원을 따로 켜고 끌 수 있었다. 이후 밝기·대비·채도의 조절을 나누고 슬라이더를 붙였다. 낮·노을·밤의 값을 직접 움직여 보면서 원하는 조합을 골랐다. 여러 효과가 합쳐진 결과를 말로만 설명하는 대신, 어느 효과를 얼마나 바꿀지 눈으로 비교할 수 있게 된 것이다.

## 위치와 픽셀까지 편집하고 다시 내보내기

7월 21일 침실 작업에서는 거실과 침실, 현재 버전과 이전 버전을 함께 비교하는 뷰어로 확장했다. 편집 기능도 세 단계로 붙였다. 먼저 컬러피커와 창빛·그림자·비네트 강도, 다음으로 가구 위치·크기, 마지막으로 연필·지우개·스포이드로 픽셀을 편집하는 기능이었다. 편집한 결과를 기존 아트 데이터 형식으로 내보내게 해, 화면에서 고른 것을 다시 코드로 설명하는 왕복도 줄일 수 있게 했다.

## 다음 방에는 같은 설명 대신 규칙과 모듈을 가져가기

거실의 합성 순서와 소품 구조, 광원·그림자·비네트 처리, 팔레트와 추출 절차를 `SCENE-RULES.md`로 묶었다. 침실에서는 하늘·산·구름·바닥·팔레트 같은 거실 모듈을 가져다 쓰고 방의 구조와 가구를 새로 만들었다. 새 소품마다 접지 그림자와 빛 차단 목록을 따로 등록하던 부분도 기본 적용과 예외 처리로 바꿨다. 같은 설명과 연결 작업을 방마다 처음부터 반복하지 않도록 한 것이다.

## 자동 완성보다 반복 작업을 줄이는 과정

이후에도 침실과 주방의 시안을 고르고 그림을 다듬는 일은 남았다. 이 과정이 좋은 그림을 자동으로 완성해 준 것은 아니다. 달라진 것은 공통 효과를 매번 다시 설명하고 구현하는 대신 재사용하고, 눈으로 결정해야 할 값은 화면에서 조절할 수 있게 된 점이다. 에셋 제작을 간략하게 만드는 데 필요했던 것은 생성 한 번을 더 잘하는 것뿐 아니라, 생성 이후의 전달·수정·확인을 반복할 수 있는 형태로 만드는 일이었다.
