## 그림 안에 이미 빛이 있었다

돌마고치의 방 장면은 낮·노을·밤과 계절·날씨에 따라 색과 빛이 바뀐다. 거실과 침실은 GPT로 만든 시안을 레퍼런스로 삼아 형태와 색을 뽑아 픽셀 장면으로 만들었다. 문제는 레퍼런스가 한 시점의 조명까지 그린 그림이었다는 점이다. 창에서 바닥으로 떨어진 빛 웅덩이, 벽난로 주변의 글로우, 화면 가장자리의 어두움(비네트), 전체에 낀 따뜻한 색조가 색 자체에 섞여 있었다.

이렇게 구워진 빛 위에 시간대 오버레이를 얹으면 빛이 두 번 들어간다. 밤 장면에도 낮의 창빛이 남고, 그것이 덜 보이게 하려면 오버레이를 약하게 써야 한다. 7월 21일 침실은 실제로 낮 조명이 구워진 추출본을 쓰고 있었고, 바닥의 큰 창빛 자국이 밤에도 보였다.

## 구운 빛을 걷어 내고 바탕만 남겼다

7월 19일 거실 실험에서 레퍼런스의 빛을 걷어 냈다(디라이팅). 주변 픽셀의 밝기를 평균 내는 큰 박스 블러로 화면의 넓은 밝기 분포를 구하고, 원본 밝기를 그 값으로 나눠 평평하게 만드는 방식이다(`albedo = g × target / blur`). 이 방식으로 넓게 퍼진 밝기 차이를 줄이면서 접지 그림자나 선반 안쪽의 좁은 그늘(AO)을 남기려 했다. 다만 밝기 차이와 색 자체에 남은 빛은 달랐다. 색조는 그대로 두고 전체에 낀 따뜻한 색만 60% 줄였다. 불꽃·촛불처럼 스스로 빛나는 것은 원래 색을 유지했다.

블러 반경보다 큰 빛 웅덩이는 이 방법으로 다 지워지지 않았다. 거실 바닥은 남은 빛을 쓰는 대신 빛이 없는 나무 판자를 절차적으로 다시 그렸다. 침실에서도 블러 반경을 조절했지만, 후속 작업에서는 바닥과 러그에 색조로 남은 햇빛이 끝내 지워지지 않았다. 그 부분은 빛이 고정되지 않은 절차 생성 그림으로 바꿨다. 밝기를 고르게 만드는 것만으로 모든 방향광을 제거할 수는 없었다.

## 빛은 렌더러가 얹는다

바탕에서 뺀 빛은 장면 위 레이어로 다시 얹었다. 해와 달은 창 크기의 빔으로, 벽난로는 거리에 따라 세 단계로 약해지는 링으로, 촛불은 작은 링으로 그렸다. 광원마다 빛을 그릴 범위인 마스크를 두고, 소품에는 빛을 막는 영역인 오클루더를 지정했다. 그래서 돌멩이를 끄면 그 그림자도 함께 사라지고 빛이 통과한다.

이 원칙을 `SCENE-RULES.md` 첫 문장으로 적었다. 소품은 빛이 없는 바탕색과 접지 그늘만 그리고, 시간·계절·날씨·광원의 색과 명암은 렌더러가 얹는다. 침실도 이 규칙에 맞춰 다시 만들었고, 그 뒤로 오버레이를 줄이지 않고 원래 강도로 쓸 수 있었다.

## 생성기를 옮기고 1,151개를 대조했다

장면 규칙은 Python 생성 스크립트(형태), CSS(팔레트·상태), HTML 조립 스크립트(광원·마스크)에 나뉘어 있었다. 7월 20일 이를 JavaScript 모듈(생성·팔레트·광원·소품·렌더러)과 Canvas 렌더러로 합쳤다. 당시 브라우저 미리보기를 쓸 수 없어, Python 결과를 정답 파일로 내보내고 JavaScript 결과와 사각형 단위로 비교했다. 9개 그룹 1,151개가 모두 일치했다.

일치시키는 과정에서 1픽셀씩 어긋나는 산술 차이 세 가지가 나왔다.

| 차이 | 원인 | 처리 |
| --- | --- | --- |
| 해시 | Python 정수는 자릿수 제한이 없지만 JavaScript 비트 연산은 32비트로 잘린다 | BigInt 사용 |
| 반올림 | Python `round()`는 짝수 쪽으로, JavaScript `Math.round`는 위로 반올림한다 | Python 방식 반올림 함수를 좌표 계산 20곳에 적용 |
| 소수 둘째 자리 문자열 | 0.625처럼 이진수로 정확히 표현되는 절반 값에서만 결과가 갈린다 | 같은 규칙의 서식 함수 추가 |

바닥과 벽이 만나는 곳의 그늘 세 줄이 빠져 있던 것도 이때 찾았다. 합친 뒤 장면 페이지는 구운 SVG 179KB에서 4.8KB가 됐다. 색 하나를 바꾸려고 Python을 다시 돌릴 필요가 없어졌고, 시간×계절×날씨 조합은 CSS 선택자 우선순위 대신 코드의 명시적 순서로 정해졌다.

## 눈으로 정할 값은 편집기로

빛을 레이어로 나누자 강도와 색을 따로 조절할 수 있게 됐다. 7월 21~22일 침실 뷰어에 이전/현재 버전 비교, 색·빛 강도 슬라이더, 소품 위치·크기 조절, 픽셀 편집을 차례로 붙이고, 결과를 기존 아트 데이터 형식으로 내보내게 했다. 시안을 볼 때마다 말로 설명해 고치던 일은 이 편집기와 모듈로 상당 부분 대신했다. 자동 저장과, 산·나무 같은 절차 생성 요소를 픽셀로 굽는 기능은 만들지 않았다.

## 검증 범위

디라이팅은 블러 반경보다 큰 빛을 다 지우지 못해 절차적 재작화나 반경 조정이 필요했다. 1,151개 대조는 생성기를 옮긴 결과가 같다는 확인이고, 그림의 품질은 낮·노을·밤 장면을 눈으로 비교해 판단했다.
