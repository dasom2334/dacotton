## 친구가 관리하던 사료 목록에서 시작했다

친구가 아픈 고양이의 사료 정보와 개인 메모를 엑셀에 관리하는 모습을 보고, 반복되는 자료 수집을 줄이고 필요한 조건으로 제품을 찾을 수 있는 냠을 만들었다. 출발점과 첫 자동화 과정은 [1화](/log/2026/08/25/nyam-automate-catalog/)에 자세히 정리했다.

## 조건으로 찾고, 나란히 비교하고, 먹인 것을 기록한다

냠은 제조사가 공개한 제품 정보를 모아 사용자가 정한 원료와 영양 수치 조건으로 제품을 찾고 비교할 수 있게 한다. 반려동물별로 피하려는 원료를 설정하고, 무엇을 먹였는지와 각 원료를 의심하는지 등의 상태도 기록할 수 있다.

결과에는 무엇을 근거로 조건에 걸렸는지, 어떤 정보가 부족한지를 함께 남긴다. 설정한 조건을 확인하는 데 필요한 자료가 부족하면 조건에 맞는다고 확정하지 않는다. 조건 대조의 결과를 보고 보호자가 다시 확인할 수 있도록 만드는 것이 중요했다.

## 실제 사용에서 새로운 제품을 찾았다

친구는 비공개 정보와 개인 메모는 기존 목록에 남겨 두면서, 냠에서 이전에는 몰랐던 회피 조건에 걸리지 않는 제품을 발견했다. 확인한 효용은 이 새로운 선택지이며, 모든 자료를 옮기거나 줄어든 시간을 측정한 것은 아니다.

## 운영하며 확인하는 것

서비스를 계속 운영하고 피드백을 반영하면서, 보호자에게 얼마나 도움이 되는지와 수익 가능성을 확인해 나간다. 친구가 요청한 상품 비교와 브랜드 추가, 빠진 성분 정보 같은 문제도 이 과정에서 살펴보고 있다.

개발 로그에는 제품을 만들며 선택한 구조와 그 이유를, 오답노트에는 잘못 처리했던 사례의 원인과 수정을 남긴다. 대표 글로는 [검색 요청의 DB 작업을 줄인 과정](/log/2026/09/11/nyam-publish-observations/), [테스트가 실제로 지키는 동작을 확인한 과정](/log/2026/09/11/nyam-testing-the-tests/), [작은 베타의 인프라를 고른 과정](/log/2026/09/13/nyam-infrastructure-choice/)이 있다.

## 기술 구성

| 맡은 일 | 사용 기술 |
| --- | --- |
| 제품 검색·비교 화면 | React 19와 TypeScript로 화면을 만들고 Vite로 빌드한다. 화면 코드 검사는 Vitest를 사용한다. |
| 제품·조건 조회 API | Python의 Django 5.2와 Django REST Framework가 요청을 처리한다. |
| 제품 원문·해석 결과 저장 | Neon의 PostgreSQL을 사용하며, 서버는 psycopg로 연결한다. |
| 제조사 웹자료 수집 | Python 수집 코드에서 curl_cffi로 웹 요청을 보낸다. |
| 서버 실행과 정적 파일 제공 | Gunicorn이 Django를 실행하고 WhiteNoise가 정적 파일을 제공한다. |
| 빌드·배포 | Docker로 화면과 서버를 하나의 이미지에 담고, GitHub Actions에서 Artifact Registry를 거쳐 Google Cloud Run으로 배포한다. |

Docker 빌드에서는 Node 22로 웹 화면을 빌드한 뒤, 그 결과물과 서버 코드를 Python 3.12 이미지에 함께 넣는다.
