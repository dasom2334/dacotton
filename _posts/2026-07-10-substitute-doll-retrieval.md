*7월 6~14일 인입·검색·로컬 모델 연결과 통합 기록을 돌아봤다.*

## 명령 다섯 개가 곧 파이프라인

CLI의 하위 명령이 그대로 처리 단계다.

| 명령 | 하는 일 |
| --- | --- |
| `ingest` | 대화 텍스트를 발화 단위(화자·본문·순서·시각)로 나눠 SQLite `refined_records` 테이블에 저장 |
| `index` | 저장된 발화마다 임베딩 벡터를 만들어 같은 DB의 `record_vectors` 테이블에 float32 BLOB으로 저장 |
| `search` | 질의를 임베딩해 모든 발화 벡터와 코사인 유사도를 비교하고 상위 k개를 돌려줌 |
| `reply` | 상황 문장으로 `search`를 돌린 뒤, 찾은 내 발화를 예시로 넣은 프롬프트를 생성 모델에 보내 초안을 받음 |
| `eval` | 상황 목록마다 `reply`를 돌려 검색 결과와 초안을 나란히 출력, 사람이 판정 |

초안은 사람이 읽고 고쳐 쓰는 용도이고 자동 전송은 없다.

## 규칙으로 읽는 입력과 모델에 맡길 입력

메신저 내보내기는 형식이 제각각이다. 특정 메신저 형식을 나열하는 대신 날짜·시각·화자 라벨·구분자 같은 일반 신호를 규칙으로 읽었다. 실제 내보내기는 날짜를 하루 한 번 구분선으로만 찍고 그 아래 줄에는 시각만 남기므로, 마지막으로 본 날짜를 기억해 시각만 있는 발화에 붙였다.

빈 줄로 나눈 구간마다, 구조 신호는 있는데 규칙이 읽은 줄이 80% 미만일 때만 로컬 생성 모델에 구간을 보내 JSON으로 받는 폴백을 붙였다. 받은 항목 중 하나라도 형식이 틀리면 전체를 버리고 규칙 결과를 유지한다. 순수 평문 구간은 모델에 보내지 않으므로, 모델 서버가 꺼져 있어도 `ingest`는 규칙만으로 돈다. 7월 10일에는 날짜 없이 시각만 반복되는 로그를 "구조 신호 없음"으로 판정해 규칙과 폴백이 모두 놓치던 경우를 고쳤다.

`index`를 따로 둔 것은 임베딩 모델이 무겁기 때문이다. `ingest`는 임베딩 모델을 아예 불러오지 않고, `index`를 실행할 때만 불러온다.

## 작은 데이터에서는 검색을 단순하게

한 사람의 대화는 수천 발화 규모라 근사 검색 없이 전부 비교해도 충분했다. 벡터 검색 확장(`sqlite-vec`)도 검토했지만 표준 라이브러리 `sqlite3`만으로 돌게 해 런타임 의존성을 0개로 유지했다. 데이터가 커지면 검색 부분만 갈아 끼울 수 있게 인터페이스 뒤에 두었다.

임베딩은 로컬 MiniLM, 생성은 Docker로 띄운 Ollama를 썼다. API 키·호출 비용과 대화를 외부로 보내는 부담은 없앴지만, 모델 적재 시간과 메모리를 직접 감당하게 됐다. Ollama를 Docker로 연결한 것은 저장소를 받아 바로 실행할 수 있게 하려는 선택이었다. 당시 macOS Docker에서는 GPU를 쓰지 못해 CPU로 추론했다.

## 검색과 생성을 따로 평가했다

[PR #19의 실행 기록](https://github.com/dasom2334/substitue-doll/pull/19)은 합성 대화 14건과 상황 5개, `qwen2.5:7b` CPU 실행이다.

| 평가 대상 | 결과 |
| --- | --- |
| 검색 (상황별 첫 결과가 관련 발화인가) | "혼났어"에 팀장에게 혼난 발화, "잠 못 자"에 지친다는 발화가 첫 결과로 나오는 등 대체로 관련 |
| 생성 (내 말투의 답장인가) | 반말과 "ㅋㅋ"가 재현된 양호 2건, 다른 언어가 섞인 2건, 모델 첫 적재 중 시간 초과 1건 |

찾아온 예시가 맞아도 초안이 그 말투를 따르지는 않았다. 초기 구현은 상황 문장을 그대로 따라 말하기도 해서, 프롬프트에 "상황을 반복하지 말고 답장을 쓰라"는 규칙을 넣었다. 한국어에 강한 다른 모델로 바꾸는 것은 다음 후보로 남겼다.

연결한 도구는 개인용 초안을 고쳐 쓰는 출발점이 됐다. 다만 과거 예시를 잘 찾는 것만으로 새 상황에 맞는 말투까지 재현되지는 않았고, 모델·프롬프트와 평가 사례를 더 다듬을 과제가 남았다.

## 검증 범위

판정은 PR에 남은 실행 결과를 해석한 것이고 고정된 채점표나 독립 평가자는 없었다. 표본이 작고 실행 실패가 섞여 있어 "말투 정확도 몇 %" 같은 수치로 바꾸지 않는다. 언어 혼입이 CPU 실행 때문인지도 따로 확인하지 않았다.
