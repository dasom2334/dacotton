7월 15~16일, 화면 시안을 실제로 쓸 수 있는 타이머로 옮겼다. 서버나 계정 없이 브라우저 안에서만 도는 앱이라, 창을 닫았다 돌아왔을 때 이어받을 것은 모두 그 기기의 저장소에 있어야 했다.

## 무엇을 저장하고 무엇이 시간에 따라 바뀌나

게임 상태 전체(현재 단계, 집중 경과, 휴식 종료 시각, 돌의 게이지, 설정)를 객체 하나로 두고 IndexedDB에 통째로 저장한다. 시간과 관련된 값은 성격이 셋으로 나뉜다.

| 값 | 어떻게 흐르나 | 창을 닫았다 열면 |
| --- | --- | --- |
| 집중 경과(`session.elapsedSec`) | 열린 화면이 250ms마다 더한다. 탭이 숨으면 기본 설정상 멈춘다 | 저장된 경과에서 다시 이어 센다 |
| 휴식 종료(`rest.endsAt`) | 절대 시각을 저장하고 남은 시간은 현재 시각과 비교해 계산 | 닫혀 있던 동안에도 흐른 것으로 계산된다 |
| 돌의 게이지 | 날짜가 바뀔 때마다 기분이 줄고, 오래 방치하면 욕구 단계가 내려간다 | 복원 직후 지난 날짜 수만큼 한 번에 정산(`SETTLE`) |

브라우저를 닫은 동안 코드가 돌고 있는 것은 아니다. 다시 열었을 때 저장된 시각과 지금 시각의 차이로 계산할 뿐이다. 그래서 "언제 저장하고, 언제 복원하고, 언제 정산하느냐"의 순서가 기록을 지키는 핵심이 됐다.

## 복원보다 저장이 먼저 돌 수 있었다

저장 경로는 두 개였다. 상태가 바뀌면 표시만 해 두고 1초마다 한 번 쓰는 자동 저장, 그리고 탭이 숨겨지는 순간(`visibilitychange`) 바로 쓰는 즉시 저장(`flushSave`)이다. 자동 저장을 1초 간격으로 묶은 것은 250ms마다 바뀌는 집중 경과를 매번 IndexedDB에 쓰지 않기 위해서다.

문제는 앱이 뜰 때다. 앱은 처음에 초기값 상태로 시작하고, IndexedDB에서 세이브를 읽어 오는 복원은 비동기로 끝난다. 그 사이에 사용자가 탭을 옮기면 즉시 저장이 돌고, 아직 초기값인 상태가 기존 세이브를 덮는다. 몇십 시간 키운 돌이 새 돌로 바뀔 수 있는 순서 문제였다. 코드 리뷰에서 이 순서 문제가 지적됐다.

그래서 복원 함수가 끝날 때(성공이든, 세이브가 없든, 손상됐든) `bootComplete`를 켜고, 그 전에는 두 저장(1초 자동 저장, 탭이 숨겨질 때의 즉시 저장)이 모두 아무것도 하지 않게 했다. 저장해야 한다는 표시는 남겨 두어 복원이 끝난 뒤 다음 1초 자동 저장 때 저장된다. 앱 시작 순서는 다음으로 고정했다.

1. 세이브를 읽고 구조를 검증한다. 버전이 낮으면 마이그레이션을 거친다
2. 지난 날짜만큼 게이지를 정산한다
3. 저장을 연다
4. 집중 중이었다면 현재 탭이 보이는지에 맞춰 일시정지 상태를 맞춘다

4번은 숨은 탭에서 저장된 집중 세션이 보이는 탭에서 복원될 때, 일시정지 상태 그대로 멈춰 있던 문제를 고친 것이다. 세이브에는 스키마 버전을 붙이고 읽을 때 필드 구조를 검사해, `settings: null` 같은 깨진 세이브가 들어와도 화면이 터지지 않고 초기 상태로 시작하게 했다. 내보내기·가져오기로 기기를 옮기거나 백업할 수 있게 했다.

## 두 탭이 서로의 진행을 덮었다

같은 앱을 두 탭에서 열면 탭마다 자기 메모리의 상태를 1초마다 같은 IndexedDB 세이브에 쓴다. 한쪽에서 집중을 끝내도 다른 쪽이 그보다 오래된 상태를 쓰면 진행이 사라진다.

브라우저의 Web Locks API로 배타 잠금 하나를 두고, 먼저 잠금을 얻은 탭만 활성 탭이 되게 했다.

| 탭 | 동작 |
| --- | --- |
| 먼저 연 탭 | 잠금을 탭이 닫힐 때까지 쥐고 복원·자동 저장을 한다 |
| 나중에 연 탭 | 복원하지 않고 "돌은 이미 다른 창에 있다"는 대기 화면만 보인다. 복원을 안 했으므로 `bootComplete` 관문에 막혀 저장도 하지 않는다 |
| 앞 탭이 닫히면 | 기다리던 탭이 잠금을 얻고 새로 로드해 최신 세이브로 시작한다 |

새로 연 탭이 활성 탭을 빼앗는 방식도 구현하다가 되돌렸다. 기존 탭이 아직 쓰는 도중에 주도권이 넘어가면 같은 덮어쓰기가 다시 생길 수 있어서, 먼저 연 탭이 끝까지 쥐는 쪽이 단순하고 안전했다. 두 탭을 실제로 열어 소유권과 승격을 확인했다.

## 다음 집중은 사용자가 시작한다

휴식이 끝났다고 다음 집중을 자동으로 시작하지는 않았다. 휴식 카운트다운은 백그라운드 탭에서 타이머가 늦춰지는 것에 대비해 Web Worker로 돌리고, 끝나면 알림으로 돌아올 시점만 알린다. iOS Safari는 홈 화면에 설치한 웹앱에서만 웹 알림을 보내므로 PWA로 만들어 GitHub Pages에 첫 배포했다.

게임 규칙은 화면과 떼어 순수한 상태 전이로 두고 현재 시각을 인자로 받게 했다. 처음에는 저장과 정산을 테스트하기 위한 구조였는데, 곧 수십 시간짜리 진행을 기다리지 않고 검증하는 기반이 됐다.

## 검증 범위

Web Locks를 지원하지 않는 브라우저는 예전처럼 모든 탭이 활성으로 동작한다. iOS 설치형 PWA의 알림과 백그라운드 워커 타이머는 당시 실기기로 확인하지 않았다.
