냠의 제품 상세 화면은 제품 하나에 대해 원재료 목록, 보장성분표(단백질·지방·섬유·수분·회분 등의 최소·최대 %), 그리고 "제조사 페이지 수집일"을 보여 준다. 이 값들은 제품마다 연결된 성분표 이력(`ProductHistory`) 중 '현재 이력' 하나에서 나온다. 정기 갱신으로 제조사 공개 정보를 다시 확인하면 새 이력이 만들어지고, 공개 단계가 제품의 현재 이력을 새 이력으로 옮긴다. 화면의 수집일은 이 현재 이력의 수집 시각(`crawled_at`)이다.

조사와 수정은 에이전트(Codex)가 했고, 나는 운영 배포를 승인하고 배포 뒤 실제 Chrome에서 화면을 다시 확인하도록 요청했다.

## 수집일은 새로 바뀌었는데 보장성분이 사라졌다

9월 20일 낮 주간 갱신을 복구하는 작업(PR #64, 15:30 KST 머지)에서 확인한 것은 갱신 명령이 성공했고, 제품 API가 200을 돌려주며, 상세 화면의 수집일이 9월 18일로 바뀌었다는 것까지였다. 그날 저녁 에이전트가 이력에 실제로 보장성분 값이 들어 있는지 세어 보니 다음과 같았다.

| 브랜드 | 운영 DB 상태 | 저장된 원문을 현재 파서로 읽으면 |
| --- | --- | --- |
| 로우즈 | 9월 8일 이력은 112개 중 107개에 보장성분이 있었는데, 9월 18일 새 이력 112개는 모두 비어 있음 | 107개에서 값이 나옴 |
| 애니몬다 | 현재 이력에 보장성분이 거의 없음(2개) | 256개에서 값이 나옴 |
| 테라펠리스 | 현재 이력에 보장성분 없음 | 28개에서 값이 나옴 |

로우즈는 원래 있던 값이 갱신으로 사라진 경우이고, 애니몬다·테라펠리스는 9월 16일 추가한 브랜드 파서로 읽을 수 있는데도 운영 DB에 반영되지 않은 경우였다. 로우즈의 경우 공개 단계가 현재 이력을 보장성분이 빈 새 이력으로 옮겼기 때문에, 상세 화면에는 최신 수집일과 함께 빈 보장성분표가 나오고 있었다. 수치 조건(예: 인 1% 이하)을 건 사용자에게는 이 제품들이 '확인 불가'로 바뀌었을 것이다. 같은 저장 원문을 현재 파서로 다시 읽으면 값이 나왔으므로, 수집은 됐지만 글자에서 숫자를 뽑는 단계에서 빠진 것이다.

## 원문을 다시 대조해 브랜드별 표기를 읽게 했다

에이전트가 브랜드마다 저장된 원문과 파서 결과를 대조해 놓치던 표기를 찾았다.

| 브랜드 | 파서가 놓치던 표기 |
| --- | --- |
| 로우즈 건식 | 표 없이 'Guaranteed Analysis' 탭 안의 문단에 `PROTEIN MIN`처럼 적음 |
| 애니몬다 | 항목 이름 칸이 비고 값 칸에 `Protein 10,5%`처럼 이름과 값을 함께 적음 |
| 지위픽 | 소문자 제목, `1,225 kcal`의 쉼표(쉼표를 못 읽으면 225로 읽힘) |
| 보래알 | `(min.)` 같은 점 붙은 표기, `2–4%` 범위, 최소·최대 표시 없는 표 |
| 오픈팜 | 콜론 없는 열량 표기 |

지위픽 키튼 제품 하나는 저장된 원문이 제품 페이지가 아니라 한국 홈페이지였다. 글로벌 주소가 한국 홈으로 넘겨 버렸기 때문이다. 같은 제품의 공식 미국 페이지에서 다시 수집하고 실제 출처를 기록했다. 원문에 없는 값은 채우지 않았다.

수정은 PR #66으로 9월 20일 22:41 KST에 머지됐다(파서 7262e6f, 지위픽 수집 9f3630c, 공개 검사 718b614). 이어 에이전트가 운영 DB를 백업한 뒤, 저장 원문을 다시 읽어 해당 이력에 보장성분을 채우는 일괄 작업을 돌렸다.

## 다음 갱신이 다시 지우지 못하게

같은 PR에서 공개 명령에 검사를 넣었다. 공개 전후로 보장성분 항목(단백질·지방·섬유·수분·회분·칼슘·인·마그네슘·타우린)이 하나라도 있는 제품의 목록을 비교해, 공개 전에는 있었는데 공개 후 사라진 제품이 하나라도 있으면 공개 전체를 되돌린다. 열량만 남은 경우는 보장성분이 있는 것으로 세지 않는다.

이 검사는 제품 하나의 문제로 그 회차의 갱신 전체를 멈췄다. 그래서 9월 21일(커밋 f199c99, PR #69, 13:50 KST 머지)에는 그 제품만 새 이력으로 옮기지 않고 이전 이력을 계속 보여 주게 바꿨다. 다른 제품은 정상적으로 새 이력으로 넘어가고, 보류된 제품은 진단 로그에 남는다.

## 복구 뒤 숫자

복구 뒤 화면에 공개된 고양이 제품 897개 중 831개에서 기본 보장성분(단백질·지방·섬유·수분·회분 중 하나 이상)이 확인됐다. 남은 66개는 여러 맛을 묶은 혼합팩·번들 63개와, 제조사 원문에 열량만 적힌 오픈팜 간식 3개였다. 브랜드 8곳의 대표 제품 API에 보장성분 값이 있는지 확인했고, Chrome에서 로우즈 제품 하나의 단백질 최소 11%·지방 최소 5%·수분 최대 78% 표시를 직접 확인했다.

이후 운영 점검은 응답이 오는지와 수집일이 바뀌었는지에 더해, 이전 이력에 있던 값이 새 이력에도 남아 있는지를 보는 일이 됐다.

## 검증 범위

831개는 기본 성분이 하나 이상 확인된 수로, 모든 영양 항목이 채워졌다는 뜻은 아니다. 수치 조건 사용자에게 '확인 불가'로 보였을 것이라는 부분은 판정 규칙에서 추론한 것이며 당시 화면으로 확인하지 않았다. 점검을 시작한 계기는 기록에 없다.
