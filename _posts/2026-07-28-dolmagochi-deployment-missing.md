## main과 라이브가 다른데 배포는 0건

7월 29일 새벽 침실 장면을 머지했는데 라이브 화면이 바뀌지 않았다. 앞서 겪은 PWA 캐시 문제가 아니었다. 이 앱은 main에 머지하면 Vercel이 GitHub 이벤트를 받아 프로덕션 빌드를 만드는 구조다. 그런데 새 머지 커밋에 대한 Vercel 배포 기록이 실패도 취소도 아니고 아예 없었고, 서비스는 7월 24일 새벽 커밋의 빌드에 머물러 있었다.

GitHub은 push 이벤트를 정상으로 보냈고(같은 이벤트로 CI는 3초 뒤 돌았다), Vercel 설정도 일시정지·브랜치·빌드 생략 조건 모두 정상이었다. 그 사이에서 이벤트가 사라진 것이다. 빌드가 시작조차 하지 않았으므로 커밋에 실패 표시도 붙지 않았다. 화면이 안 바뀐다는 걸 사람이 눈치챌 때까지 아무 신호가 없었다.

## 배포가 생겼는지를 직접 확인한다

밀린 배포는 Vercel의 Deploy Hook(호출하면 배포를 시작하는 URL)으로 복구했다. 그리고 main에 머지될 때마다 도는 GitHub Actions 감시를 붙였다.

| 확인하는 것 | 근거 |
| --- | --- |
| 이 커밋으로 프로덕션 배포가 생겼나 | Vercel 배포가 끝나면 GitHub Deployments에 Production 기록이 남는다. 보통 30초, 느릴 때 1분 43초여서 5분까지 기다린다 |
| 없다면 왜 없나 | Vercel은 빌드가 끝나면 커밋에 `Vercel` 상태를 남긴다. 상태가 있으면 빌드 실패, 없으면 이벤트 유실 |

이벤트 유실일 때만 Deploy Hook을 불러 스스로 복구하고, 빌드 실패면 훅을 부르지 않고 실패로 알린다. 같은 커밋을 다시 빌드해도 또 실패할 뿐이기 때문이다. 복구에 성공해도 경고를 남겨, 반복되면 Vercel에 문의할 근거로 삼게 했다. 감시는 배포 기록을 읽는 권한만 쓴다.

자세한 구분 조건은 [배포 미생성 오답노트](/mistakes/2026-07-28-dolmagochi-deployment-missing/)에 남겼다.

## 검증 범위

Vercel 내부에서 이벤트가 왜 사라졌는지는 알아내지 못했다. 만든 것은 같은 현상이 다시 생기면 알아채고 배포를 다시 거는 감시 작업이다.
