파일 생성 경로를 갖춘 다음에는 외부 번역 제공자에 대한 의존을 줄여보려 했다. 이 선택으로 API 호출 제한 대신 로컬 모델의 메모리와 실행 시간을 다루게 됐다.

## 호출 비용을 줄이려다 로컬 모델의 자원을 다루게 됐다

외부 API의 키와 비용, 일일 한도에 덜 의존하려고 로컬 번역 모델도 연결했다. 모델을 실행하는 것 자체는 됐지만, 긴 작업에서 GPU 메모리가 쌓이며 중단되는 문제가 생겼다.

입력 크기를 줄이고 GPU 사용 비율을 낮추고 정리를 기다리는 조치가 이어졌다. 마지막에 주목한 것은 컨텍스트를 다시 만들던 방식이었다. 상태를 비우기 위해 큰 자원을 재생성하면서 메모리가 오히려 겹쳐 올라갔다. 같은 컨텍스트를 쓰고 블록 사이의 캐시를 비우도록 바꾼 뒤, 증상을 누르려고 낮췄던 GPU 레이어 비율을 다시 올렸다.

이 과정으로 로컬 실행 경로를 다듬었지만, 모델이 끝까지 실행되는 것과 출력 PDF가 읽기 좋은 것은 여전히 다른 문제였다.
## 1차 완성과 가독성 사이에서 멈췄다

현재는 PDF를 받아 번역된 PDF를 내보내는 1차 구현을 마친 뒤 중단한 상태다. 사용자 관점에서 남은 큰 문제는 가독성이다. 번역문이 원래 문장보다 길어졌을 때 폰트를 줄이거나 끝을 잘라 맞추는 것으로는 읽을 수 있는 문서를 만들기 어렵다. 원본 폰트 크기와 줄바꿈, 배경색 처리를 개선하려던 작업도 남았다.

API나 다른 인터페이스를 더 붙이는 후속 계획은 있었지만, 지금 다시 시작한다면 먼저 다룰 것은 출력물이다. 실제 문서를 놓고 문장이 빠지지 않는지, 원래 배치와 읽는 순서가 유지되는지 확인하는 일이 앞선다. 현재 추가 개발 일정은 없다.
