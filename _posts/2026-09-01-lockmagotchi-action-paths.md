[앞 실험](/log/2026/08/29/lockmagotchi-shared-state/)에서 앱·홈 위젯·라이브 배경화면이 배고픔 값 하나를 함께 쓰게 됐다. 배고픔은 0~100 사이 정수이고 이름과 달리 높을수록 배부른 상태다. 밥주기를 한 번 누르면 10 오른다. 남은 질문은 잠긴 화면에서 이 값을 바꿀 수 있느냐였다. 8월 29일부터 9월 1일까지 Pixel 7 프로필 에뮬레이터(API 36, 순정 Android 잠금화면)에서 경로를 하나씩 시험했다.

## 잠금화면의 입력은 배경화면까지 오지 않았다

가장 원한 모습은 잠금화면에 보이는 캐릭터를 그대로 누르는 것이었다. 라이브 배경화면은 터치 이벤트를 받을 수 있으므로, 탭할 때마다 숫자가 올라가는 카운터를 배경화면에 그려 확인했다.

| 위치 | 결과 |
| --- | --- |
| 홈화면 빈 곳 탭 | 카운터 0 → 1 |
| 잠금화면 여러 위치 탭 | 변화 없음 |

잠금화면에서는 운영체제의 잠금 화면 계층(키가드)이 입력을 먼저 처리하고 배경화면으로 넘기지 않는다. 배경화면은 잠금화면에서 **보이기만** 한다. 표시와 조작을 다른 수단에 맡겨야 했다.

## 잠금 중에 누를 수 있는 경로를 하나씩 확인했다

| 경로 | 잠금 중 실행 | 사용자가 할 일 | 판단 |
| --- | --- | --- | --- |
| 알림 + 액션 버튼 | 됨. 잠금화면이 떠 있는 상태에서 밥주기를 누르자 배고픔 50 → 60, 인증 화면·앱 열림 없음 | 알림 권한 허용 | 쓰지 않음 |
| 잠금화면 바로가기 | 안 됨. 시스템 항목(손전등, 방해 금지, 기기 제어 등)만 지정 가능 | — | 불가 |
| 기기 제어(Device Controls) | 됨. PIN 잠금 상태에서 배고픔 70 → 80 | 컨트롤 추가, "잠금 해제 없이 사용" 켜기 | 채택 |
| 잠금화면 위젯 | 판정 불가 | 위젯 켜기·배치 | 보류 |
| 잠금화면 대체 앱 | 화면 전체를 가질 수 있음 | 상시 알림, 배터리 최적화 예외, 보안 잠금 해제 | 기각 |

알림은 잠금 해제 없이 동작했다. 하지만 순정 잠금화면에서 알림은 접힌 채로 떠서 버튼을 보려면 한 번 펼쳐야 하고, 사용자가 잠금화면 알림을 끄면 경로 자체가 사라진다. 무엇보다 폰을 꾸미려고 설치한 앱이 알림 카드를 상시 띄우는 모습은 만들고 싶은 장면과 달라서 쓰지 않기로 했다.

잠금화면 대체 앱은 첫 화면을 통째로 그릴 수 있었다. 대신 계속 떠 있는 서비스와 그에 따른 상시 알림, 제조사 배터리 관리에 의한 미표시 위험, 그리고 사용자에게 시스템 보안 잠금을 끄게 하는 부담이 따랐다. 가벼운 꾸미기 앱이 요구할 대가로는 컸다.

## 기기 제어는 됐지만 한 단계 안쪽에 있었다

기기 제어는 원래 스마트홈 기기를 켜고 끄라고 시스템이 제공하는 패널이다. 앱이 `ControlsProviderService`를 구현하면 "밥주기" 컨트롤을 등록할 수 있고, 등록하면 잠금화면 왼쪽 아래에 기기 제어 바로가기가 생긴다.

8월 30일 첫 시도에서는 PIN 잠금 상태에서 컨트롤을 누르자 PIN 키패드가 떴다. 컨트롤은 기본적으로 인증을 요구하기 때문이다. 컨트롤에 `setAuthRequired(false)`를 주고, 사용자가 설정에서 "기기 제어를 잠금 해제 없이 사용"을 켠 상태에서 다시 누르자 잠금은 그대로인 채 배고픔이 70에서 80으로 바뀌었다. 둘 중 하나라도 빠지면 인증 화면으로 넘어간다.

조작이 성공한 것과 자연스럽게 돌보고 싶은 경험은 따로 평가해야 했다. 사용자는 잠금화면의 바로가기를 **길게 눌러** 패널을 연 뒤 컨트롤을 눌러야 한다. 앱을 컨트롤 제공자로 등록하고 설정도 켜야 한다. 패널은 스마트홈용 타일 격자라 다마고치처럼 보이지도 않았다.

## 잠금화면 위젯은 에뮬레이터에서 확인할 수 없었다

9월 1일에는 Android 16 QPR2부터 픽셀 폰의 잠금화면에 위젯이 돌아왔다는 사실을 확인했다. 기존 홈 위젯이 별도 API 없이 잠금화면에도 놓인다면, 배경화면이 첫 장면을 맡고 위젯이 조작을 맡는 구조가 가능했다.

API 36.1 에뮬레이터 이미지에서는 관련 기능 플래그가 켜져 있었지만, 설정에 "잠금화면 위젯" 토글이 없고 스와이프해도 위젯 페이지가 열리지 않았다. 이 UI는 픽셀 기기용 시스템 빌드에만 들어 있었다. 실제 픽셀 기기 없이는 판정할 수 없어 보류로 남기고, 이미 잠금 중 실행까지 확인한 기기 제어를 조작 수단으로 유지했다.

## 당시에는 작은 타협으로 보였다

예쁜 장면은 배경화면이, 돌보기 버튼은 다른 화면이 맡으면 된다고 봤다. 표시와 조작을 나누면 가능한 범위 안에서 계속 진행할 수 있었다. 다만 "폰을 켜자마자 캐릭터를 누른다"는 처음 목표와의 거리는 여기서 생겼다. 다음 실험은 기기 제어 패널 안을 직접 만든 화면으로 바꿔 그 거리를 줄일 수 있는지였다.

## 검증 범위

모든 판정은 순정 Android 에뮬레이터 기준이다. 목표 기기였던 삼성 갤럭시·폴더블과 잠금화면 위젯은 실기기로 확인하지 못했다.
