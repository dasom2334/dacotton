## 세이브는 주소에 묶여 있었다

돌마고치에는 서버가 없다. 돌의 상태와 기록은 플레이어 브라우저의 저장소(IndexedDB)에 저장되고, 이 저장소는 사이트 주소의 도메인 단위로 나뉜다. 그래서 같은 게임이라도 주소가 바뀌면 브라우저는 다른 사이트로 보고, 세이브는 빈 상태로 시작한다.

7월 22일 광고를 검토하면서 공개 주소가 필요해졌고, 친구들에게 나눠 주려면 어차피 오래 쓸 주소가 있어야 했다. 당시 게임은 GitHub Pages의 하위 경로(`/dolmagochi/`)에서 돌고 있었다. 호스팅을 한 번씩 옮길 때마다 친구들의 세이브가 초기화되는 문제가 생긴다.

## 하위 경로냐 서브도메인이냐

Claude Code는 내 도메인을 쓰면 주소가 호스팅 업체와 상관없이 유지된다고 정리했다. 나는 처음에 개인 도메인 아래 `/dolmagochi` 경로에 얹으려 했다. 그런데 여러 게임을 만들 계획이라 한 도메인에 모두 묶이면 무겁다는 우려가 들었다. Claude Code는 그렇다면 게임마다 서브도메인을 주는 편이 맞다고 했다. 서브도메인은 저장소가 게임마다 나뉘고, 홈 화면 앱(PWA)이 쓰는 경로 설정도 바꿀 필요가 없었다.

## 서브도메인과 Vercel로 옮겼다

내가 `dacotton.dev` 도메인을 사고 Vercel과 DNS 설정을 했다. Vercel은 사이트를 도메인 최상위에서 바로 서비스하므로 하위 경로용 설정이 필요 없었다. Claude Code는 빌드 설정의 기본 경로를 `/dolmagochi/`에서 `/`로 바꾸고, 어떤 주소로 들어와도 게임 화면을 돌려주는 설정을 넣었다(커밋 f071ec2).

첫 배포에서는 화면이 하얗게 떴다. 경로 수정이 아직 main에 올라가지 않아 Vercel이 옛 설정으로 빌드한 것이었다. main은 직접 올릴 수 없는 보호 브랜치라 PR #43으로 올렸고, 7월 23일 00:23 KST에 병합됐다. 같은 PR에서 README의 플레이 주소를 `https://dolmagochi.dacotton.dev`로 바꾸고 GitHub Pages 배포 작업을 지웠다. 그 작업이 테스트와 데이터 검사도 돌리고 있었으므로, 내 승인을 받아 배포 없이 빌드·테스트·검사만 도는 CI 작업을 새로 만들었다.

## 결과

병합 뒤 Claude Code가 새 주소를 브라우저로 열어 게임과 방 그림, 분위기 바가 최상위 주소에서 정상으로 뜨는 것을 확인했다. 이후 방문 통계를 위해 쿠키를 쓰지 않는 Vercel 방문 분석도 붙였다(PR #44, 00:50 KST).

이제 호스팅을 다시 옮겨도 주소가 같으면 세이브는 그대로다. 다만 이미 GitHub Pages 주소에서 쌓인 세이브는 자동으로 넘어오지 않는다. 이 경우는 7월 15일부터 있던 세이브 내보내기·불러오기로 옮겨야 했다.

## 검증 범위

예전 GitHub Pages 사이트를 내리는 일은 내가 할 일로 남겨 뒀고, 언제 내렸는지는 기록에 없다. 친구들이 실제로 세이브를 옮겼는지는 확인하지 않았다.
