대타출동 인형은 과거의 내 대화에서 관련 발화를 찾아, 지금 답하기 곤란한 상황의 답장 초안을 만드는 로컬 도구다. 초안은 사람이 읽고 수정하며 자동으로 전송하지 않는다.

*7월 6~14일 인입·검색·로컬 모델 연결과 통합 기록을 돌아봤다.*

## 규칙으로 읽는 입력과 모델에 맡길 입력을 나눴다

메신저 내보내기와 평문에서 날짜·시각·화자를 먼저 규칙으로 읽었다. 구조가 있지만 규칙으로 읽지 못하는 구간에는 모델을 사용하는 경로를 붙였다. 서버가 응답하지 않을 때도 가능한 규칙 처리는 유지했다. 무조건 모든 대화를 모델에 보내는 것보다 실패 위치를 좁힐 수 있었다.

인입과 임베딩도 나눴다. 대화를 저장할 때마다 무거운 임베딩 모델까지 불러올 필요는 없었다. 이후 관련 발화를 찾고 현재 상황과 함께 제공해 초안을 만들었다. 7월 10일에는 날짜 없이 시각만 반복되는 로그를 규칙과 폴백이 모두 놓치는 경우를 고쳐 입력 범위를 넓혔다.

## 작은 데이터에서는 검색을 단순하게 유지했다

한 사람의 수천 발화를 전제로 벡터를 SQLite BLOB에 저장하고 코사인 유사도로 전수 비교했다. `sqlite-vec` 확장도 검토했지만 이 단계에서는 설치·환경 의존성을 늘리지 않는 선택을 했다. 확장 설치가 실제 실패해서 포기한 사례는 아니다. 데이터가 커지면 전수 비교 비용이 커지므로 검색 인터페이스는 교체할 수 있게 뒀다.

로컬 MiniLM 임베딩과 Ollama 생성은 API 키·호출 비용·대화 외부 전송 부담을 줄이는 대신 모델 적재 비용을 가져왔다. Ollama는 ‘clone해서 실행할 수 있는 구성’을 우선해 Docker로 연결했다. 당시 macOS Docker 경로는 CPU 추론이어서 네이티브 가속보다 이식성을 택한 절충이었다.

## 검색 성공과 생성 품질을 따로 평가했다

[PR #19의 실행 기록](https://github.com/dasom2334/substitue-doll/pull/19)은 **합성 대화 14건·5개 상황**, `qwen2.5:7b` CPU 실행이다. PR에 기록된 검색 판정은 각 상황의 첫 번째 결과가 상황과 관련되는지를 보는 방식이었다. 예를 들어 ‘혼났어’에는 팀장에게 혼난 발화가, ‘잠 못 자’에는 지친다는 발화가 검색됐다고 남아 있다. 생성은 반말과 ‘ㅋㅋ’가 재현된 두 사례를 양호로 분류했고, 두 사례에는 다른 언어가 섞였으며 하나는 모델을 처음 불러오는 중 타임아웃이 났다. 이 분류는 PR에 남은 실행 결과 해석이다. 별도 평가자의 신원이나 고정된 채점표까지 확인되지는 않아, 독립 평가 점수로 취급하지 않는다.

따라서 ‘말투 정확도 40%’ 같은 일반 성능으로 환산하지 않는다. 표본이 작고 실행 실패까지 섞인 결과다. 다른 언어 혼입이 CPU 실행 때문이라고도 분리 검증하지 못했다. EXAONE 등 한국어 모델 교체는 다음 후보였지, 개선 효과를 확인한 결과가 아니었다.

연결한 경로는 개인용 초안을 고쳐 쓰는 출발점이 됐다. 과거 예시를 잘 찾는 것만으로 새 상황에 맞는 말투까지 재현되지는 않았다. 모델·프롬프트와 평가 사례를 더 다듬을 과제가 남았다.
